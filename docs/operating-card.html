Every session

The loop

The two things that have gone wrong were both left-behind work: a commit on one Mac, unpushed, and a second agent in a repo already being worked. The loop closes both.

Start

  1. Open the workspace and pull all three. Fast-forward only. If a pull refuses, see the box below before doing anything else.

    code ~/Developer/rux.code-workspace
for r in rux-ds rux-ln-atlas rux-ln-notes; do git -C ~/Developer/$r pull --ff-only; done

  2. Health-check only the repo you are about to touch. Read the exit code, not the output.

    cd ~/Developer/rux-ds       && npm install --ignore-scripts && npm run verify
cd ~/Developer/rux-ln-notes && node tools/check.mjs
cd ~/Developer/rux-ln-atlas && python3 tools/check.py

  3. Start agents on the tree you just pulled. One agent per repo at a time. Agents do not pull; you did.

Work flows downstream, one repo at a time

Finish, commit and push the upstream repo before you sync the downstream one. The sync scripts refuse a dirty upstream, so this is the order the tools already expect.

Content atlas → notes

  1. atlas: edit · python3 tools/check.py · commit · push
  2. notes: sh tools/sync-guides.sh
  3. node tools/build.mjs · node tools/check.mjs
  4. commit · push — the push is the publication

Design system rux-ds → notes

  1. rux-ds: edit · npm run verify · commit
  2. tag if a milestone or a class left (CHANGES.md) · push
  3. notes: sh tools/sync-ds.sh · build · check
  4. commit · push

End

  1. Commit in every repo you touched. The hook checks the message: type(scope): Subject, subject ≤ 50 characters, body wrapped at 72, no AI trailer of any kind.

  2. Push every repo you touched, then confirm each one reads level with origin and lists no file. The branch line alone cannot see an uncommitted or untracked file.

    for r in rux-ds rux-ln-atlas rux-ln-notes; do git -C ~/Developer/$r fetch -q; git -C ~/Developer/$r status -sb; done
## main...origin/main      ← one such line per repo and NOTHING under it;
                          a file listed there is work only this Mac has

  3. Close the lid only after the push. Nothing stays local on either Mac. Ever.

Never

  • Hand-edit vendor/ or data/guides/ in notes. The next sync erases the edit; the fix belongs upstream.
  • Edit a generated file in rux-ds: css/rux.css, css/rux.min.css, kitchen-sink.html, portal.html, the README stats table.
  • Work around a "dirty tree" or "wrong identity" refusal. It is holding a rule for you.
  • Run two agent sessions in the same repo. Different repos at once are fine.
  • Send anything from notes or atlas into rux-ds except an ask with invented content that check-publishable clears. Never a real page.

When a pull refuses

It means you committed on the other Mac and forgot to push before switching. Both sides have real commits. Put yours on top of theirs, re-check, push.

git pull --rebase origin main   # then re-run that repo's check, then: git push

A conflict in a generated file — css/rux.css, kitchen-sink.html, portal.html, the README stats table, MEASURED, guides/*.html — is never resolved by editing it. Take either side, run the generator (npm run verify, node tools/build.mjs, node tools/measure.mjs), then git add the result and git rebase --continue. The hooks do not run while a rebase replays commits, so the check you re-run afterwards is the only one.

Once per Mac · under ten minutes

Setting up a machine

Do every step on both Macs so they are identical. Every step ends in something you can see.

Before you start: git, Node 22.13 or newer (rux-ds declares it and CI holds it), Python 3.9 or newer, the code shell command (VS Code: Command Palette → “Shell Command: Install 'code' command in PATH”; the app install does not add it), and a way for git to reach the private atlas repo. A GitHub password does not work for that: create a personal access token with repo scope at github.com/settings/tokens and paste it as the password when the atlas clone prompts; Apple git keeps it in the keychain after that. Check with git --version, node --version, python3 --version.

  1. Clone all three into ~/Developer, under exactly these names, side by side. The layout is load-bearing: notes' checks look for ../rux-ds and ../rux-ln-atlas and refuse or report a gap without them.

    mkdir -p ~/Developer && cd ~/Developer
git clone https://github.com/rux-sm/rux-ds.git
git clone https://github.com/rux-sm/rux-ln-atlas.git
git clone https://github.com/rux-sm/rux-ln-notes.git

  2. Set the identity once, globally. Every commit hook in the family refuses any other name or address.

    git config --global user.name "rux" && git config --global user.email "rux.dev@pm.me"

  3. Arm the commit hooks. This is per clone and git cannot carry it, so a fresh clone commits with no checks and nothing tells you. Note the different path in notes.

    git -C ~/Developer/rux-ds       config core.hooksPath .githooks
git -C ~/Developer/rux-ln-atlas config core.hooksPath .githooks
git -C ~/Developer/rux-ln-notes config core.hooksPath tools/githooks

  4. Install and run the first check in each. You want exit 0 from verify, check: clean from atlas, and gates passed from notes with no NAMES WERE NOT CHECKED line above it. Three things look like failures and are not: npm warns that it skipped install scripts (expected; read the exit line), an atlas warning names a content defect (the text-cache warning clears once the venv line has run; the venv is per machine and gitignored), and notes prints where the sibling checkouts stand under “siblings (live)”, which is information and never a failure. Commit nothing during setup.

    cd ~/Developer/rux-ds       && npm ci --ignore-scripts && npm run verify; echo "exit $?"
cd ~/Developer/rux-ln-atlas && python3 tools/build.py && python3 tools/check.py
cd ~/Developer/rux-ln-atlas && python3 -m venv .venv && .venv/bin/python -m pip install -q pypdf && .venv/bin/python tools/text.py
cd ~/Developer/rux-ln-notes && node tools/check.mjs

  5. Create the VS Code workspace that holds all three, so one window pulls and shows everything.

    cp ~/Developer/rux-ds/docs/rux.code-workspace ~/Developer/
code ~/Developer/rux.code-workspace

    The file lives in rux-ds under docs/ and is copied up because VS Code wants it beside the three folders; edit the copy in rux-ds, never the one in ~/Developer. Auto-fetch keeps the ahead/behind arrows honest without pulling; pull-tags brings rux-ds's version tags down; rebase-when-sync puts your commits on top of the other Mac's instead of making merge commits. Scan depth 0 stops VS Code listing carbon-website/, IBM's docs clone that rux-ds keeps gitignored as a quarry; it is not yours and never needs syncing, and no Mac needs it: nothing in npm run verify reads it, and a Mac that wants it clones github.com/carbon-design-system/carbon-website into rux-ds/, where .gitignore already hides it. Always open VS Code from this file — the window title ends in “(Workspace)” — and in the Source Control view each repo gets its own row. Pull from there or with the loop on page 1; what matters is all three, before any agent starts. An up-arrow on a row at the end of a session is a commit only this Mac has.

  6. Prove the hooks are armed, in all three. A commit with a forbidden trailer must be refused. A refusal leaves nothing behind. If one is accepted, that hook is not armed: run git reset --hard HEAD~1 there and redo step 3.

    for r in rux-ds rux-ln-atlas rux-ln-notes; do git -C ~/Developer/$r commit --allow-empty -m "test: Probe

Co-Authored-By: nobody"; done
# expect, three times:  commit-msg: Co-Authored-By trailer — commits are authored by rux alone
